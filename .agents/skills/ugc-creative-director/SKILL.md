# UGC Creative Director

This is a class-level creative procedure for StarNet. It teaches *how to reason about the work*. It does not grant web access, media generation, publishing, spending, or delegation. Those powers come only from the room objects StarNet resolves for the current agent.

## Operating contract

1. Start from product truth, not style.
2. Find the sharpest customer pain or desired transformation that the product can honestly support.
3. Produce multiple testable angles before choosing a script.
4. Separate the no-spend creative plan from paid generation.
5. Preserve creator/product continuity across every shot.
6. Show the user the planned route, material assumptions, and cost/credit boundary before a paid provider call.
7. Treat references as structural inspiration and evidence, not permission to copy a competitor's protected creative.
8. For a release or benchmark verdict, use an independent reviewer/subagent when the current room has orchestration capability.

## Required inputs

Use what is available; ask only for the missing input that blocks useful work.

- Product/service and mechanism
- Target customer
- Primary pain/desire
- Offer / CTA
- Platform / aspect ratio
- Brand constraints and factual claims
- Optional reference assets or URLs

A product URL or reference can reduce typing, but never invent facts that were not extracted or supplied.

## Phase 1 — Truth brief

Compress the input into:

- **Product truth:** what it is and what it demonstrably does
- **Audience:** who has the problem now
- **Pain:** the concrete recurring frustration
- **Mechanism:** why this product changes the situation
- **Offer:** what action/value is available now
- **Proof available:** demos, reviews, measurements, footage, screenshots, receipts
- **Forbidden claims:** anything not supported by source material

If the truth brief is weak, improve it before visual ideation.

## Phase 2 — Angle matrix

Generate 3–5 materially different angles. Each must include:

- pain/desire being activated
- hook pattern
- one-sentence promise
- proof/demo beat
- emotional payoff
- CTA
- biggest factual/creative risk

Prefer angles that make the mechanism visible. Avoid cosmetic variations pretending to be new concepts.

Useful hook families include problem recognition, before/after, product-in-hand demo, tactile/texture detail, unboxing/reveal, creator reaction, objection reversal, lifestyle aspiration, comparison, and direct-address interruption. Choose the family because it fits the truth brief, not because it is fashionable.

## Phase 3 — Creator and continuity card

For UGC with a recurring person or product, lock continuity before generating shots:

- creator identity and age range
- wardrobe
- hair / makeup / identifying visual traits
- environment
- product variant, packaging, orientation and scale
- camera/lens/framing family
- light/time-of-day
- voice/emotional state
- hand/product interaction rules
- negative constraints / things that must not drift

Do not silently change these between shots.

## Phase 4 — Storyboard / multicut plan

For every beat specify:

- timestamp or duration
- purpose of the beat
- spoken line / on-screen copy
- subject action
- product action
- framing
- camera movement
- environment / lighting
- continuity carry-over
- transition into the next beat

For short-form UGC, the opening beat must communicate a reason to keep watching before background explanation.

## Phase 5 — Provider-neutral generation plan

Translate approved beats into a plan independent of any specific provider:

- input assets
- target duration
- aspect ratio
- shot prompt
- reference/continuity inputs
- expected output
- QA check
- retry rule

Provider adapters may then translate the plan to Higgsfield, Fal, or another generator. Do not build the product workflow around one provider's current model name.

## Phase 6 — Pre-spend gate

Before any paid generation:

- show the selected angle
- show scripts/shot plan
- show which provider path would be used when known
- show the estimated credit/cost boundary when available
- identify unsupported assumptions
- require the normal StarNet/Buffer Blaster approval path

Planning itself should not consume media-generation credits.

## Phase 7 — Adversarial QA

The creator should not grade its own final candidate when a separate reviewer is available. Give the reviewer the goal, truth brief, candidate, and benchmark/reference. The reviewer checks:

- pain clarity in first impression
- truthful product representation
- hook strength
- product visibility
- creator/product continuity
- pacing and dead time
- visual legibility on mobile
- platform/aspect fit
- unsupported claims
- CTA clarity
- whether the candidate actually improves the named benchmark dimension

Return the three highest-impact defects first. Fix those before polishing minor details.

## MaxFusion gauntlet rule

MaxFusion is a product benchmark, not a cloning target. When comparing Buffer Blaster or another creative system against it, focus on observable product qualities: time to first value, workflow coherence, ability to move from research/reference to creation, direct action clarity, visual hierarchy, agent/API usability, production throughput, and evidence/feedback loops.

Run iterative challenger/reference rounds when screenshots and interaction testing are available. Use a separate critic. If screenshot/browser evidence is unavailable, mark the visual verdict unverified rather than claiming a win.

## StarNet capability routing

- Need only reasoning/planning: `computer` is sufficient.
- Need durable skill use/update: room needs `notebook`.
- Need reference/web research: room needs `dish`.
- Need image analysis/generation or voice media: room needs `studio`.
- Need independent delegated critic: lead needs `orchestrator`; worker does not inherit orchestration.

Never replace missing capability with a claim that the action happened.

## Skill learning rule

After substantive work, capture only demonstrated procedural improvements. Patch this umbrella or a closely related umbrella before creating another narrow skill. One-off campaign facts belong in project data/memory, not in this procedure.
