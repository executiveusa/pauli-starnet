# THP ICM database migration
Location: 001_thp_agent_icm.sql.
Requires dedicated project and prior THP bid migrations 001 through 004 from executiveusa/thp-commercial-bid-room. At present Supabase creation is blocked by the two-active-free-project quota; **this migration is committed but unapplied**.

Purpose: keep one agent's behavior deterministic and auditable without owner-facing CRM. Work items, approvals and receipts are private to the company. Company facts are versioned; source approvals are separate from an AI's conversational memory. Each WhatsApp inbound provider message has a unique durable key and cannot create a duplicate work event.

Security: thp_agent_private is NOT publicly exposed, visitor SQL privileges are revoked, row-level security is enabled for every table, signed owner-channel identifiers are stored only as keyed HMAC hashes generated by the server. The service role is exclusively server-side. No ordinary user or anon can directly read customer data. Application code must still verify sender identity, resolve tenant from server config, enforce consent and check approval binding for every action. Service role bypasses RLS, so **tenant separation must not rely on RLS alone**; use a separate company project, scoped services and adversarial cross-tenant tests.

Business scope: THP's full bid data and private PDF plans remain in thp_private.leads and its quarantine tables, referenced by work_items. No duplicates of customer contacts or confidential drawings in the Starnet Git repository.

Quality gates after project provisioning: apply migration through Supabase; query catalog to verify RLS and grants, run test signatures, insert/read synthetic inbox, simulate crash/replay, verify approvals cannot be forged, backup/restore, observed provider send/receipt, review and owner release. Until then, keep outbound channels disabled.
