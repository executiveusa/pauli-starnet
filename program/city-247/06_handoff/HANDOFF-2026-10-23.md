## 4. The open problem: approved work never comes back
Evidence: #63 approved 2026-10-15 18:22Z, #64–#68 by 2026-10-17 14:51Z. Zero comments from the foreman and no labels added.

The two most likely causes are both server config, so both are UNVERIFIED:
1. **Dispatch cannot reach the gateway.** The foreman defaults to `GATEWAY_URL=http://127.0.0.1:4000`, but the gateway on
   prod-city-1 listens on **4001** (`verify.sh` was changed to 4001 in commit 215e7a2a). If
   `/etc/pauli-starnet.env` has no `GATEWAY_URL`, every dispatch fails. After 3 tries the item shows
   `BLOCKED "failed 3 times"`, but only on the server board.
2. **Results are not written back.** The foreman comments on issues and adds `needs-review` only when
   `FOREMAN_GITHUB_WRITE=1`. Without it, missions that finished would leave no trace on GitHub.

Run these on prod-city-1 and paste the output (they print no secrets):
```sh
grep -E '^(GATEWAY_URL|FOREMAN_GITHUB_WRITE|STARNET_DISTRICT_STATE)=' /etc/pauli-starnet.env | sed 's/=.*/=<set>/'
grep -E '^GATEWAY_URL=' /etc/pauli-starnet.env                     # the URL itself is not a secret
cd /root/pauli-starnet && git log --oneline -1 && git status --short | head
journalctl -u starnet-foreman --since "-30 min" --no-pager | tail -40
curl -s -H "Authorization: Bearer $GATEWAY_BEARER_TOKEN" http://127.0.0.1:4001/v1/districts \
  | jq '{age_seconds, stale, errors, d: [.districts[]|select(.active!=false)|{district,action,issue,question,reason,mission_id}]}'
```
How to read the results:
- `impact` **RUNNING** with a `mission_id`: missions are running. Set `FOREMAN_GITHUB_WRITE=1` so results reach the issues.
- **BLOCKED "failed 3 times: …"**: read the error. If it is a connection error, set `GATEWAY_URL=http://127.0.0.1:4001`.
  The state file remembers failed attempts, so after fixing it, clear the attempts for those issues: stop the timer,
  back up the state file, then delete `districts.<id>.attempts` (and `last_error`) for those issue numbers.
- **stale: true** or HTTP 503: the timer is not writing the board. Check `systemctl status starnet-foreman.timer`,
  and check that `STARNET_DISTRICT_STATE` is the same path in the foreman env and the gateway env.
- The checkout is older than `6389a28f`: run `git pull` (fix for oldest-first ordering).

Done when the first approved issue (#63) has a result comment from the foreman and the `needs-review` label.
