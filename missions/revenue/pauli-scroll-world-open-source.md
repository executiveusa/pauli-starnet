# Mission: Productize Pauli Scroll World as an open-source anti-slop workflow

## Objective

Package Pauli Scroll World as a reusable open-source workflow that helps builders turn grounded project state into a cinematic scrolling world without inventing activity, results, agents, or progress.

## Done-when

A release candidate exists on a reversible branch with all of the following:

- a crisp product boundary that separates the open-source workflow from private credentials, owner data, proprietary deployment state, and anything involving Instinct;
- a runnable quickstart from a clean checkout using zero paid keys for the documented proof path;
- an input contract for real project state and an output contract for scenes, movement, overlays, and evidence references;
- the anti-slop gate: no scene or claim is emitted unless grounded in supplied state or an explicit source, and unknown state is shown as unknown rather than filled in;
- a sample project using sanitized or fictional data;
- the existing montage zero-key video proof located, verified, and referenced by its real repository path or stable URL without copying secrets or private material;
- architecture, workflow, customization, contribution, security/privacy, and license-readiness docs;
- automated checks for clean install, zero-key sample generation, deterministic or bounded output, grounding-veto behavior, secret scanning, and broken links;
- a release checklist and draft release notes, with public release left unperformed.

## Inputs and context

- Repo: `executiveusa/pauli-starnet`, canonical branch `feat/harness-backend`.
- Start with `docs/GRAPHICS_UPGRADE_PATH.md`, the Scroll World code and assets it names, `frontend/app/autopilot.js`, `frontend/app/autojobs.js`, `sidecar/threadmine.js`, and their tests.
- Reuse the existing anti-slop principle: grounded candidates only, confidence gate, and silence or explicit unknown state when evidence is insufficient.
- Montage is the media operator in the workforce catalog. A zero-key montage video proof is reported to exist; verify the actual artifact before citing it. If it cannot be found, record that as blocked rather than recreating or claiming it.
- This mission packages existing proof and workflow. It does not promise photorealism, production hosting, revenue, or compatibility that has not been tested.

## Allowed tools and skills

- Repository read/write on a new branch; local shell for build, test, render, hashing, link checks, and secret scans.
- Existing repository graphics, scroll, montage, anti-slop, workforce, docs, QA, and test assets.
- Existing zero-cost/local rendering paths only.
- Heisenberg may delegate code, docs, asset audit, test, and QA work to existing internal workers.
- No external publishing, social, package-registry release, marketplace listing, paid API, payment, outreach, production deployment, credential, or destructive tools.

## Budget and gates

- Cash budget: $0. No paid model, rendering, hosting, storage, or distribution services.
- Messages to other people: prohibited. Prepare copy only.
- Public publishing: prohibited. Do not make a repository public, publish a package, create a release, upload a video, or announce the project.
- Money: prohibited.
- Irreversible deletion: prohibited. Preserve existing assets and history; use a branch.
- License ambiguity, third-party asset provenance, private data, or credential exposure is a hard stop for release readiness and must be itemized.
- Logins/account approvals: stop and report the exact account, screen, and action needed.

## Receipt format

Return one JSON receipt plus a short Markdown summary containing:

- `mission_id`, `status`, `started_at`, `completed_at`, `branch`, and final commit SHA;
- `outcome`: paths to source, docs, sample, tests, release checklist, and draft release notes;
- `validation`: clean-checkout commands, test counts, proof-render result, anti-slop negative test, secret-scan result, and link-check result;
- `evidence`: hashes and real paths/URLs for the verified montage proof and generated sample artifacts;
- `provenance`: license and source status for every redistributed asset or dependency;
- `updated_state`: what is ready for an approval-gated public release;
- `blocked`: missing proof, provenance, credential, login, or technical blocker;
- `not_proven`: public demand, installation outside tested environments, production scale, commercial results, and public availability until those events actually occur.
